Introducción

Aplicación web full-stack

⌘

Front-end (React)

Interfaz con la que interactúa el usuario. Se ejecuta en el navegador y gestiona la presentación y el estado de la vista.

⚙

Back-end (Node.js + Express)

Concentra la lógica de negocio y el acceso a los datos. Expone una API que el cliente consume.

  • Ambas partes usan JavaScript: un único lenguaje en toda la aplicación.
  • Se desarrollan, despliegan y escalan por separado.
  • Se comunican mediante el protocolo HTTP con datos en JSON.
1 · Conceptos teóricos

Modelo cliente-servidor

Un cliente solicita un recurso o servicio y un servidor lo procesa y responde. En la web, el cliente es el navegador (React) y el servidor es el programa Node.js.

Cliente
Navegador · React
Petición HTTP →
← Respuesta (estado + JSON)
Servidor
Node.js · Express

Petición-respuesta

El cliente siempre inicia. El servidor responde con código de estado, cabeceras y, normalmente, un cuerpo de datos.

Sin estado (stateless)

Cada petición es independiente. La identidad se envía en cada solicitud, por ejemplo con un token.

Separación de responsabilidades

El cliente presenta; el servidor aplica lógica y datos. Cada parte escala por separado.

1 · Conceptos teóricos

Arquitectura de componentes en React

React es declarativo: se describe cómo debe verse la interfaz para un estado dado y React actualiza el DOM. La interfaz es un árbol de componentes (funciones que reciben datos y devuelven JSX).

Composición

Los componentes complejos se arman combinando componentes pequeños, con una sola responsabilidad.

Flujo de datos unidireccional

Los datos bajan del padre al hijo mediante props (solo lectura). Los hijos avisan hacia arriba con funciones recibidas por props.

Estado (state)

Datos internos que cambian con el tiempo (useState). Al cambiar, el componente se vuelve a renderizar.

DOM virtual y reconciliación

React compara la nueva descripción con la anterior y aplica en el DOM real solo las diferencias.

1 · Conceptos teóricos

Ciclo de vida de un componente

Tres fases: montaje (se inserta en el DOM), actualización (cambian props o estado) y desmontaje (se elimina). En componentes funcionales se maneja con useEffect.

FaseComponentes de claseComponentes funcionales
MontajecomponentDidMountuseEffect(() => {…}, [])
ActualizacióncomponentDidUpdateuseEffect(() => {…}, [dependencia])
DesmontajecomponentWillUnmountfunción de limpieza devuelta por useEffect
El efecto se ejecuta después de pintar el componente: es el lugar adecuado para pedir datos al servidor, suscribirse a eventos o iniciar temporizadores. La limpieza evita fugas de memoria. En desarrollo, React.StrictMode ejecuta los efectos dos veces a propósito para detectar errores de limpieza.
1 · Conceptos teóricos

Asincronía en JavaScript y Node.js

JavaScript ejecuta el código en un único hilo: una operación lenta síncrona (archivo, base de datos, API) bloquearía todo. La asincronía permite iniciar la operación, seguir con otras tareas y retomar el resultado cuando esté listo.

1

Callbacks

Funciones que se ejecutan cuando termina la operación. Anidarlos genera código difícil de leer.

2

Promesas

Promise con .then y .catch: representan un resultado futuro y encadenan pasos.

3

async / await

Código asíncrono con apariencia secuencial; los errores se manejan con try/catch.

Evolución: callbacks → promesas → async/await. Hoy se usa async/await en toda la E/S del servidor.
1 · Conceptos teóricos

El Event Loop de Node.js

Tu código JavaScript corre en un solo hilo, pero Node atiende muchas conexiones gracias a la E/S no bloqueante gestionada por el Event Loop (biblioteca libuv). La E/S se delega al sistema operativo o a un pool de hilos (4 por defecto: archivos, criptografía, DNS) y el callback se ejecuta al terminar.

1 · Timers

Callbacks de setTimeout y setInterval cuyo tiempo venció.

2 · Pending callbacks

Callbacks de E/S diferidos por el sistema.

3 · Idle / prepare

Uso interno de Node.js.

4 · Poll

Recibe eventos de E/S (red, archivos) y ejecuta sus callbacks.

5 · Check

Callbacks programados con setImmediate.

6 · Close callbacks

Eventos de cierre, p. ej. socket.on('close').

↻ El bucle repite estas fases. Entre una operación y otra se vacían dos colas de prioridad: primero process.nextTick y luego las microtareas (promesas y async/await).
1 · Conceptos teóricos

Event Loop: orden de ejecución

Entre una fase y otra, Node.js vacía las colas de prioridad en este orden:

OrdenQué se ejecuta
1Código síncrono
2process.nextTick
3Microtareas (promesas y async/await)
4Timers (setTimeout, setInterval) y el resto de fases del bucle
Consecuencia práctica: como el hilo es único, un cálculo pesado o un bucle largo bloquea el Event Loop y deja sin respuesta a todos los clientes. Las tareas intensivas deben evitarse en el servidor, dividirse o delegarse a worker threads o a procesos aparte.

API REST, peticiones HTTP y JSON

REST (Representational State Transfer): el servidor expone recursos identificados por URL y el cliente los manipula con los verbos estándar de HTTP. Los datos viajan en JSON: ligero, legible y nativo de JavaScript.

VerboEjemplo de rutaAcción
GET/api/v1/tareasObtener la lista de tareas (200 OK)
POST/api/v1/tareasCrear una tarea nueva (201 Created)
PUT / PATCH/api/v1/tareas/5Reemplazar o modificar parcialmente la tarea 5
DELETE/api/v1/tareas/5Eliminar la tarea 5
Códigos de estado: 200 éxito · 201 creado · 400 datos inválidos · 401/403 sin autenticación o permiso · 404 no encontrado · 500 error interno del servidor.
2 · Análisis arquitectónico

Flujo de integración cliente ↔ servidor

  1. El usuario actúa en la interfaz y un componente de React dispara un efecto o un manejador de eventos.
  2. El cliente envía una petición HTTP con fetch o Axios: método, URL, cabeceras y, si corresponde, cuerpo JSON.
  3. Express recibe la petición y la pasa por los middlewares (CORS, lectura de JSON, autenticación, validación).
  4. El router la dirige al controlador, que invoca la capa de servicios con la lógica de negocio.
  5. La capa de datos consulta la base de forma asíncrona; mientras espera, el Event Loop atiende otras peticiones.
  6. El servidor devuelve una respuesta JSON con su código de estado.
  7. React actualiza el estado con setState y vuelve a renderizar solo los componentes afectados.

Cliente

components piezas de interfaz · pages vistas · hooks lógica reutilizable · services llamadas HTTP.

Servidor

routes URL y verbos · controllers req/res · services lógica de negocio · models datos · middlewares validación, auth y errores.

Cada carpeta tiene una única responsabilidad: facilita las pruebas y el trabajo en equipo.
3 · Buenas prácticas

Buenas prácticas y su justificación (1/2)

Arquitectura en capas en el servidor

Rutas, controladores, servicios, modelos

Separa responsabilidades, facilita las pruebas y permite cambiar la base de datos o el framework sin reescribir la lógica.

Componentes pequeños, hooks y capa de servicios

En el cliente

Fomenta la reutilización y evita mezclar llamadas HTTP con la presentación; el código es más fácil de mantener.

API REST correcta y versionada

Verbos y códigos HTTP, /api/v1

Hace la API predecible para quien la consume y permite evolucionar sin romper clientes existentes.

Variables de entorno

Archivo .env

Evita exponer credenciales en el código y permite distintas configuraciones por entorno.

3 · Buenas prácticas

Buenas prácticas y su justificación (2/2)

Validación y manejo centralizado de errores

Nunca se debe confiar en los datos del cliente; un único middleware de errores garantiza respuestas coherentes.

Seguridad

CORS restringido, helmet, límite de peticiones, bcrypt, JWT

Reduce los riesgos comunes: accesos no autorizados, fuerza bruta y filtración de contraseñas.

No bloquear el Event Loop

async/await en toda la E/S

Con un solo hilo, una operación síncrona pesada paraliza a todos los usuarios.

Git, pruebas y logs

Control de versiones, pruebas automatizadas, registro de eventos

Permiten trabajar en equipo, detectar errores a tiempo y diagnosticar fallos en producción.

Conclusiones

Ideas clave

  • Una app full-stack se apoya en el modelo cliente-servidor: React gestiona la interfaz con componentes, estado y efectos; Node.js atiende peticiones con su Event Loop no bloqueante.
  • Ambas partes se integran mediante una API REST que intercambia JSON sobre HTTP.
  • Las prácticas que más inciden en un sistema mantenible, seguro y escalable: arquitectura en capas, validar y proteger la API y no bloquear el Event Loop.
